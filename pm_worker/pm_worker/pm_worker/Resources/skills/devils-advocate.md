## Purpose
方案讨论越到后期越没人敢反对：沉没成本加群体一致等于确认偏误温床。魔鬼代言人审查指定一个明确「唱反调」的角色，按结构化清单穷举反方论点并分强度，让最强质疑在拍板前被迫现身。评审 Agent 的毒舌人格写死在 prompt，本技能提供其可调用的审查框架：问什么、怎么分级、怎么收口。

## 步骤
1. 指定反方角色并做利益切割：反方不为方案质量负责，只为「质疑是否足够强」负责
2. 按清单穷举论点，每条问一遍：
   - 目标错了吗（解决的是真问题吗）
   - 时机错了吗（窗口是否已关或未开）
   - 方案成立吗（核心假设哪个最脆）
   - 成本被低估了吗（隐性成本、维护成本）
   - 竞品会怎么反击
   - 我们执行得动吗（能力与资源）
3. 每条论点标强度：致命（成立则方案作废）/ 严重（需修改）/ 一般（接受并监控）
4. 正方逐条回应：给证据、修改方案、明确接受风险，三者必居其一，不许「下次再说」
5. 未闭合的致命论点转入风险登记册，落盘必须带可观测的触发信号
6. 审查记录（论点 + 强度 + 回应）归档，供封板与复盘引用

## 反模式
- **为反对而反对**：反方角色为证明存在感，把字体、措辞级别的琐碎也列上来——琐碎质疑稀释注意力，真正的致命论点被淹没。反方的衡量标准是「最强的一条够不够强」，不是条数。
- **论点无强度分级**：十条论点平铺给决策者——「字体可能不好看」与「核心假设无数据支撑」并列展示，等于把分级工作推给最忙的人。致命 / 严重 / 一般三档强制先分再议，致命项未闭合则方案不封板。
- **只审不闭环**：论点列完会议结束，没人认领回应——未回应的论点不会消失，只会在上线后变成事故。每条论点必须有动作（证据、修改、接受风险三选一），致命未闭合项转风险登记并带触发信号，否则审查只是风险仪式。

## 一个例子
健身App v1.1 封板前审查。反方最强论点：「周报自动生成依赖 iOS 健康数据权限，若平台收紧权限，坚持反馈闭环整体断裂」——强度致命（核心价值链单点依赖）。正方回应：修改方案，增加降级路径（手动录入完成度，周报继续生成），并把「iOS 权限政策变更」转入 risks.jsonl，触发信号＝权限相关 API 行为变更。次强论点「小白对周报无感」标严重——以周报页仿真原型的用户测试回应，结论回写。审查记录归档，封板时致命项全部闭合或带信号挂账。
