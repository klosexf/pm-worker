## Purpose
竞品分析最常见的失败不是没做，而是做成功能清单对照，产出「跟进清单」而非「差异化依据」。竞品简报用五段固定结构（定位 / 核心功能 / 差异点 / 可借鉴 / 风险）在 1-2 天内产出一页纸，每条事实带出处，结构与调研环输出 schema 直接对齐，成为 PRD 可引用的输入而非一次性阅读物。

## 步骤
1. 圈定 2-3 个竞品：直接对位 1-2 个 + 替代方案 1 个（含「不解决」），超过 3 个先砍
2. 按五段结构逐竞品填写：
   - 定位：一句话 + 目标人群
   - 核心功能：只列服务其目标用户主任务的功能，不抄应用商店全清单
   - 差异点：对我方定位构成威胁的点与空位点（写清「对谁而言」）
   - 可借鉴：具体到交互、策略或数据，注明出处文件
   - 风险：我方切入后竞品最可能的反应与代价
3. 每条事实标注来源（05-analysis/ 文件路径或链接）；推测条目显式标「推测」
4. 末尾合成一页「格局结论」：空位在哪、凭什么守得住
5. 产物落 05-analysis/，供 PRD 引用时带路径

## 反模式
- **功能对照表陷阱**：逐功能打勾的对照表只能得出「别人有我也要有」——差异点（别人有但不服务我方用户、或做得过重）恰恰藏在「不全有」的判断里，对照表把它平均掉了。用「服务哪个任务」替代「有没有」来比。
- **事实与推测混写**：截图里看到的是事实，「它应该是靠社区拉留存」是推测——混写后 PRD 引用会把猜测固化为决策依据。每条标出处或标推测，检索时才可分档降权。
- **简报变百科**：把公司沿革、融资历史全写进去，一页纸变十页，决策者读不到差异点与风险——简报的读者是要做取舍决策的人，与决策无关的信息删。

## 一个例子
健身App 对 Keep 的简报：定位「全民健身平台，重心在进阶内容生态」；核心功能「课程库 + 社区 + 数据看板，主任务服务长期训练者」；差异点「社区氛围偏晒成绩的老手（对小白是威胁也是空位）、打卡链路短（威胁）」；可借鉴「打卡完成动效与连续天数外显——出处：竞品截图 05-analysis/keep-01.png」；风险「Keep 若出小白模式（隐藏社区），空位窗口关闭」。格局结论：不打内容对齐，打「无社交压力的坚持反馈」。PRD 引用时标注出处路径。
