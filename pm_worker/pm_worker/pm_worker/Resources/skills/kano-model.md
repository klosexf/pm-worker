## Purpose
功能池直接拉通排序，会把「不做会死」的和「做了惊喜」的混在一个队列里抢资源。KANO 模型先把需求按「缺失/满足与满意度的关系」分成基本型、期望型、兴奋型（另有无差异、反向），分类之后再排优先级——基本型保底、期望型做主差异化、兴奋型限量择优，砍需求砍的是无差异项。

## 步骤
1. 先过目标用户画像：分类锚定人群，同一功能对不同人群类型不同
2. 每个功能配正反两问：「有 X 你感觉如何 / 没有 X 你感觉如何」，按喜欢、理所当然、无所谓、能忍受、不喜欢五档作答
3. 按答案组合映射五类：基本型 / 期望型 / 兴奋型 / 无差异 / 反向
4. 无差异与反向项剔除，记录剔除理由
5. 优先级：基本型全保 → 期望型按 RICE 排序做主 → 兴奋型限量择优做记忆点
6. 标注问卷样本量与置信度；版本迭代时复盘分类迁移

## 反模式
- **全标基本型**：跳过画像直接按常识分类，把「训练打卡」「数据精度」全标基本型——本项目小白用户对卡路里误差并不敏感，数据精度实为期望型。误标基本型会让资源被伪刚需锁死，真正的期望型差异化反而排不上。分类前先过画像（见方法论卡 kp_001 注记）。
- **兴奋型排最高优先**：兴奋型提供超预期愉悦但缺失不致命——把它排在基本型前面，产品会在「没做稳就炫技」里翻车。兴奋型是锦上添花的记忆点，预算应优先保障基本型齐全与期望型领先。
- **分类一次定终身**：竞品普及会让兴奋型变期望型、期望型变基本型（打卡曾是兴奋型，现在是基本型）——不复盘的分类随时间失真，版本迭代时应带着上版分类结果重新过一遍。

## 一个例子
健身App v1.1 功能池分类：训练打卡——小白「没有就不用」，基本型，P0 保底；周报自动生成——「越智能越满意」，期望型，主线差异化；3D 动作演示——「这个可以有」，兴奋型，限量做 3 个高频动作；卡路里精度调优——画像确认：小白不看误差细节，期望型而非基本型，降级处理；社区动态——无差异偏反向（社交压力），剔除。结论：v1.1 范围＝打卡（基本保底）+ 周报（期望主打），与 RICE 排序结果互证。
