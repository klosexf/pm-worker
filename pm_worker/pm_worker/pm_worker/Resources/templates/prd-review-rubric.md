# PRD 六维评审清单（prd-review-rubric）

> 用途：⑤ 评审环节打分的知识底座；独立毒舌评审（分支）的输出依据。输出：六维各 0-10 分 + 每个扣分点的理由与修改建议；评审意见落盘归档，不阻塞主线、不自动打回——是否修改由用户决定。
> 读取方式：规范路由确定性读取本目录最新版（不走向量检索——过期规范比没有规范更危险）。本清单随产品成熟度演进，版本间更新后旧版即失效。
> 判定输入：本清单 + 被评 PRD + 上游已确认产物（模块-页面映射表、原型页面清单、澄清要点表）——评审本质是「与上游对账 + PRD 自身一致性检查」，不是自由发挥的作文批改。

## 通用规则
- 每维先逐项勾选判定标准，再按未通过项扣分；每个扣分点必须给理由与修改建议，禁「感觉不好」式评价
- 版本兼容：本清单对齐 13 章标准模板结构；结构升级前生成的旧版 PRD 按其生成时模板版本评，不追溯扣章缺
- 与漏项雷达四档声明的关系（全文适用）：
  - ✅ 已覆盖＝对账结果，须列具体名称，禁「均已覆盖」式空话——本清单勾选项即对账维度
  - ❓ 可能遗漏＝等输入：PRD 中因信息不足标「待定」的项属合法状态不扣分；该标待定而未标才扣分
  - ⏭️ 刻意不展开＝边界声明：需求概述 3.4「范围-不包含」与「本版不做」属此类，写明原因即是方案合理性维的加分证据
  - 💀 致命漏洞假设＝证伪：现有信息即可推翻的漏洞，重扣；需要用户回答才能消除的进 ❓，两者不得互相挪用，同一条两边都写的归 💀
- 红线（零容忍）：数据指标数字非用户提供且未标「实施期建立基线」或「待定」——文档质量维直接 0 分，全文红色标注。编造的数字会直接变成错误的验收标准。

## 一、需求完整性
判定标准：
- [ ] 13 章骨架齐全（文档基本信息 / 修订记录 / 需求概述 / 产品目标与成功指标 / 用户分析 / 设计与原型 / 功能清单 / 业务流程 / 详细设计 / 性能与兼容性 / 发布计划 / 上线效果验证 / 协作与依赖；lean 档一章不少、要点式可指认）
- [ ] 需求概述首句为目标收敛句（为【目标用户】在【场景】下提供【核心能力】，以实现【差异化价值】——本版本交付【范围收敛】）
- [ ] 功能需求与模块-页面映射表及原型页面/流程一一对应，无「文档里的孤儿功能」
- [ ] 每个页面在详细设计 ① 页面概览配 ASCII 布局图（与映射表及原型页面清单对账，漏任一页面即不通过；凭空多画清单外页面同样视为缺陷）
- [ ] 正文内嵌功能架构图（6.1 信息架构）与核心流程图（8.1 业务流程）（```mermaid 各一张，与已确认结构产物一致，模块与流程节点不得凭空增删改名；缺任一张或与结构产物对不上即不通过）
- [ ] 详细设计每页 7 子项齐备（① 概览 ② 流程交互 ③ 行为规则与状态机 ④ 异常边界 ⑤ 权限角色 ⑥ 埋点 ⑦ 验收 eval；lean 档每页 ①③⑦ 3 项）
- [ ] 行为规则表为用户行为→系统响应的唯一事实来源；状态完整性检验与状态穷举三步法已执行（中间态有合法状态、逆向与特殊用户群有穷举）
- [ ] 每条功能有优先级与验收标准
- [ ] 北极星指标五要素齐全（期望结果 / 基线或「实施期建立基线」/ 目标值 / 测量时间点 / 口径）
- [ ] 指标口径可算账：每条量化指标的口径至少给出分子、分母、统计时间窗三项；确实没有的显式标「口径待补」并进待定问题清单，不得留空当已决
- [ ] 口径来源诚实：由 Agent 起草的口径已在记录块标 assumed 并带假设说明、经口径卡确认后才转 confirmed，未把起草的口径写成用户既定事实；已登记口径记录内不含任何数值（数值只允许出现在 4.2 表其余列）
- [ ] 口径单一事实源：4.2 的口径位置只写 `[[SPEC:指标名]]` 引用、不自行另写一套口径文字；落盘正文不残留未渲染的 `[[SPEC:`，也不出现正文与记录两套定义（同一指标的分母被写成两种人群即不通过）
- [ ] 验收 eval 按页分级足额（🔴 核心页与 AI 功能 5-10 条、🟡 普通页 3-5 条；AI 功能强制不可省略）
- [ ] 无上游输入之外的新假设
- [ ] 待定问题显式列清单，未混入正文当已决事项

典型扣分点：章节缺失；PRD 写入结构与原型中不存在的功能；页面缺布局图或布局图与原型页面清单对不上；缺功能架构图/核心流程图或图与已确认结构产物对不上；详细设计子项缺漏或行为规则表缺切片；验收 eval 缺分级足额或缺失败模式；该标待定而未标。
与雷达关系：❓ 档是完整性的合法出口——信息不足本身不扣分，不声明才扣分；本维勾选项即 ✅ 档的对账对象，勾选结果可直接回填雷达声明。

## 二、方案合理性
判定标准：
- [ ] 优先级排序有依据；命中 RICE 时按 RICE 排序且附各因子分与说明
- [ ] 需求概述 3.4「范围-不包含」明确且带原因（引用 rejections 更佳）
- [ ] 方案与问题陈述一致，不是为功能找理由（solution looking for a problem）
- [ ] 关键决策可回链决策日志（跨阶段影响 / 不可逆 / 有真实备选的决策记全五要素）
- [ ] 基本型需求优先于兴奋型（KANO 常识校验：兴奋型不得挤占基本型资源）

典型扣分点：优先级「凭感觉」且无说明；「范围-不包含」缺失或写成「做好 X」；目标与功能脱节、目标章与功能章各说各话。
与雷达关系：⏭️ 档（刻意不展开 + 原因）是本维核心证据，「范围-不包含」写得好是加分项；💀 档未闭合的致命假设直接压低本维分数。

## 三、用户价值
判定标准：
- [ ] 每条功能可追溯到目标画像与核心场景
- [ ] 价值主张具体可感知（禁「提升体验」类空话）
- [ ] 数据指标衡量用户价值而非虚荣指标（设反指标护栏更佳）
- [ ] 用户故事 So that 主语是用户，且删掉功能名后价值仍成立

典型扣分点：伪需求（未过目标用户画像、按常识拍分类）；指标只看规模不看价值；故事写成功能说明书。
与雷达关系：💀 档「核心价值假设一旦不成立全盘崩塌」类条目重扣本维；❓ 档「用户价值未验证」类待定项必须在待定问题清单中可见，否则按漏报扣分。

## 四、技术可行性
判定标准：
- [ ] 依赖与集成点显式列出（系统 / 数据 / 平台 / 上游版本）
- [ ] 性能与兼容性章有可量化口径
- [ ] 风险每条带应对或降级方案；致命风险带可观测触发信号且已入风险登记册
- [ ] 技术假设与事实分开标注

典型扣分点：依赖黑箱（「后续技术评估」）；「高性能」类不可测口径；核心价值链单点依赖且无降级路径。
与雷达关系：💀 档的落盘规则（无可观测触发信号不允许落盘）即本维闭环要求；触发信号缺失按致命项处理，本维不高于 3 分。

## 五、文档质量
判定标准：
- [ ] 术语全篇一致（同一事物一名到底）
- [ ] 无歧义与不可测表述（「流畅」「智能」类词已改写为可观察行为或删除）
- [ ] 引用事实标注出处文件路径
- [ ] 所有数字有来源：用户提供，或显式标「实施期建立基线」/「待定」
- [ ] 篇幅与档位匹配（lean 2-4 页 / standard 5-10 页 / full 8-15 页）

典型扣分点：AI 编造数值（零容忍，本维 0 分）；出处缺失；档位错配（低风险小功能写成十页长文、高风险产品两页糊弄）。
与雷达关系：✅ 档「禁空话、列具体名称」与本维可测性要求同源；编造数字比 💀 更重——💀 是诚实的假设，编数是错误的事实。

## 六、原型一致性
判定标准：
- [ ] PRD 功能与已确认原型的页面 / 流程一一对应
- [ ] 原型中的页面状态（空态 / 失败态 / 边界态）在详细设计 ④ 异常与边界、⑦ 验收 eval 中有覆盖
- [ ] 文档描述的交互与原型实际跳转一致
- [ ] 结构或原型回退修改并重新确认后，PRD 已按规则标「已过期」并分级标注影响范围

典型扣分点：文档与原型各说各话；PRD 凭空描述原型中没有的交互；过期状态未标注导致下游实施依据失效。
与雷达关系：本维判定即 PRD 阶段雷达「与上游对账」（PRD 对结构 + 原型）的展开——对账项逐一可勾选，对不上的项同时进雷达声明与本维扣分。

## 输出格式
- 六维分数（各 0-10）+ 总评 + 扣分点清单（维度 / 未通过条目 / 理由 / 修改建议）
- 评审意见供用户参考落盘，不阻塞主线、不自动打回——是否修改由用户决定
