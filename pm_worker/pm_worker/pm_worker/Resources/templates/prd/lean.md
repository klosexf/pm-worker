# PRD 模板 · 精简版（lean）

> 档位定位：简单迭代 / 低风险小功能。选档依据：三维度评分（技术复杂度 / 风险影响 / 范围广度，各 0-10）均值 <4 自动选本档，用户可一键切换三档任一。
> 页数预算：1-2 页。本文件是「给 AI 的生成骨架」：按各章生成要点产出内容，{{}} 为占位符，由上游已确认产物与用户对话填充。
> 输入基准：已确认结构（02-structure/模块-页面映射表.md 与核心流程图）+ 已确认原型（03-prototypes/ 页面清单）+ 澄清要点表（01-requirements/澄清要点表.md）+ 可选调研产物（05-analysis/）。结构或原型未确认（confirmed.json 缺失）不得进入生成。
> 章节合并：本档允许八章骨架合并为三章——「背景与目标」（含 概述与背景 / 目标与非目标 / 用户与场景）、「功能需求」（含 功能需求分级 / 关键非功能约束）、「指标与边界」（含 数据指标 / 依赖与风险 / 验收标准）。骨架一章不少，全部要点式，每条 1-2 句，不展开成段。

## 生成约束（三档通用，违反任一即不通过）
1. 功能需求与模块-页面映射表及原型页面/流程一一对应；结构与原型中不存在的功能不得写入 PRD
2. 引用调研事实标注出处文件路径；不引入上游输入之外的新假设
3. 数据指标数字 100% 来自用户（四步对话式获取），Agent 只引导对话，不建议、不编造任何具体数值
4. 结构或原型回退修改并重新确认后，已生成的 PRD 自动标「已过期」并分级标注影响范围（局部 / 全部）
5. 每个页面必配 ASCII 线框图（text 代码块，区块级极简即可），与映射表页面一一对应，漏任一页面即不通过

## 一、背景与目标

- 目标：{{1-2 条，可衡量或可判定}}；非目标：{{至少 1 条，写明刻意不做什么及原因}}
- 用户与场景：{{目标人群 + 核心使用场景，各一句，与澄清要点表一致，不新造画像}}

## 二、功能需求
生成要点（每条功能 3-5 行）：

- 每条附一句用户故事（As a… I want… So that…）+ 1-2 条验收标准（Given-When-Then 要素）
- 命中 RICE 方法论时按 RICE 排序并附各因子分与排序说明
- 页面线框图：每个页面一张极简 ASCII 线框图（text 代码块，区块级即可），与映射表页面对应，漏任一页面即不通过
- 关键非功能约束：{{仅列本版有硬约束的项（权限、数据来源、性能口径），一行一条；无则写「本版无特殊约束」}}

## 三、指标与边界
生成要点：
- 数据指标（四步对话式定义，逐指标走完四步，生成到本章时触发）：

  2. 有无基线：{{有 → 用户提供的当前值；无 → 该指标标「实施期建立基线」}}
  3. 目标值：{{用户给的数字；用户跳过则该指标标待定}}
  4. 测量时间点：{{点选或自填，如上线后 30/60/90 天}}

- 依赖与风险：{{依赖项 1-3 条 + 风险 1-3 条，每条风险带应对或降级方向，一行写完}}
- 验收标准：{{Given-When-Then；全档附 5-10 条可执行验收用例，每条含：场景 / 输入 / 判定标准 / 失败模式}}
