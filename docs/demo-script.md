# PM Copilot · 5 分钟演示脚本

> 对应 design.md §11 演示脚本。纪律：**每一步做完动作后停 10 秒，讲一句技术决策**——演示的胜负手不是流程有多长，而是这十句技术决策说得有多准。所有话术为原文，可直接照读。
>
> 配套物料：3 分钟录屏分镜（附录 A）、30 秒 GIF 分镜（附录 B）。示例项目统一用「健身打卡 App」。

- [ ] 两条待发送的话术打在备忘录里（见 Step 1、Step 6，照抄即可）

## Step 1（0:00–0:35）模糊念头 → 澄清对话（含记忆覆盖）

**动作**：新建项目，输入框打字（逐字打出，别粘贴）：「想做个健身打卡App」。Agent 苏格拉底式追问，每轮只问一个问题、附 2–4 个候选选项——直接**点选**一个候选作答（演示「可点选」）。第 2 轮回答时先说「不做多用户」；第 3 轮改口：「其实要支持家庭成员共享」。

**停 10 秒**：让大家看清思考卡——「思考中」的流光，以及完成后折叠的摘要行「思考了 Ns · M 步 · 技能 ×K」；再让改口后的那一轮回复出现在屏幕上。

**技术决策（话术原文）**：「注意我刚才改口了——早期我说不做多用户，后来要家庭共享。这个产品的记忆层用**覆盖语义**：新结论覆盖旧结论，旧条目标失效并留回链，不并存。因为**过期记忆比没记忆更危险**——两条约束同时生效，产物必然自相矛盾。」

## Step 2（0:35–1:10）要点表确认 + 确认坞

**动作**：澄清 5 轮（或提前收束）后，对话流里出现**澄清要点表**（目标用户 / 核心场景 / 核心价值 / 约束 / 待定问题）。输入框上方弹出**确认坞停靠卡**——点「① 确认并进入下一阶段」→ 展开确认摘要（将执行什么 / 推进到哪）→ 提交。

**停 10 秒**：让确认记录胶囊落在对话流里，让大家读一遍五字段要点表。

**技术决策（话术原文）**：「不确认不推进。确认闸口不是写在 prompt 里请求模型自觉，是**状态机的不变量**——`confirmed.json` 没写入，下一阶段的代码进不去。人和 Agent 的分工是：模型负责收敛，人负责拍板。」

## Step 3（1:10–1:50）结构一键生成——Mermaid 断网渲染 + 对话改图

**动作**：结构 Agent 产出功能架构图 + 核心流程图 + 模块-页面映射表。**当场关 Wi-Fi**，点开 `02-structure/architecture.md`——Mermaid 图照常渲染（源码/预览双视图）。然后对话里说：「把打卡模块拆出一个小目标子模块」。Agent 改图并**展示变更差异**。最后点「确认结构并进入原型」。

**停 10 秒**：断网状态下图仍在渲染；再让大家看一眼变更差异高亮。

**技术决策（话术原文）**：「两个点。一，mermaid.js 是**打包进 App bundle 的**，断网也能渲染——E15 的失败模式『引用 CDN 断网白屏』从架构上消灭。二，改一张图几秒钟，改原型要重新生成——**图是比原型便宜得多的干预点**，所以结构阶段放在原型前面，结构问题在几秒钟的层面暴露，而不是在 PRD 层面返工。」

## Step 4（1:50–2:20）原型一键生成 + 确认闸口

**动作**：原型 Agent 基于已确认结构生成单文件 HTML，WKWebView 内嵌预览。**点两三个页面跳转**（页面清单来自映射表，流程来自核心流程图）。点「确认原型」闸口按钮。

**停 10 秒**：页面跳转时把左栏文件树和映射表对齐着看——每个页面对应一个模块。

**技术决策（话术原文）**：「原型是**单文件 HTML、零外部依赖**——无 CDN、无网络请求，断网可打开、任何场合能演示。页面对映射表**一一对应**，不凭空增删：原型不是设计稿，是已确认结构的可点击形态。」

## Step 5（2:20–2:45）⌘D 证明时刻——E11 / E12（差异化核心）

**动作**：**按 ⌘D** 切开发者模式检查器。指着两处念出来：① **未命中 skill 列表**——13 个技能列在那里，正文一行都没进上下文；② 检索 trace 的 **scope 过滤说明**——「已过滤 N 条 · 跨项目 N 条」。

**停 10 秒**：这是全演示最重要的 10 秒，让「未命中 skill 列表」完整停在屏幕上。

**技术决策（话术原文）**：「大多数 AI 产品能告诉你它用了什么，**没人能当场证明它没用什么**。这个面板可以：未命中的 13 个技能正文一 token 都没进上下文——省的是钱，防的是指令互相干扰；跨项目过滤计数为证，项目 A 的约束一条不会串进项目 B——scope 隔离写在**检索层**，不是靠 prompt 叮嘱模型自觉。这是 E11 和 E12，也是最低成本的差异化。」

## Step 6（2:45–3:20）PRD 三档 + 漏项雷达四档

**动作**：进入 PRD 阶段，**先亮模板选档评分卡**——三维度（技术复杂度 / 风险影响 / 范围广度）各 0–10，每维一句理由锚定上游已确认产物。演示**一键切换**：标准版切精简版再切回来。PRD 生成后展示：功能需求与结构映射表及原型页面**一一对应**；每轮末尾的**漏项雷达四档声明**（✅ 已覆盖列具体名称 / ❓ 可能遗漏 / ⏭️ 刻意不展开+原因 / 💀 致命漏洞假设）；数据指标章的四步对话式定义（数字 100% 来自用户）。

**停 10 秒**：评分卡 + 四档声明并排停在屏幕上。

**技术决策（话术原文）**：「PRD 模板**不走 RAG**——分级模板集走确定性路由固定取最新版，因为向量检索会召回历史版本，**过期规范比没有规范更危险**。评分卡为什么敢亮出来？因为评分依据锚定的是上游已确认产物，不是『看起来挺复杂』。还有数据指标：Agent 只引导对话，**不建议、不编造任何数值**——编出来的漂亮数会直接变成错误的验收标准。」

## Step 7（3:20–3:40）风险三态——红队是哨兵不是烟花

**动作**：右栏「漏项雷达」Tab，点开风险登记册。指给大家看**人话三态**：还盯着 / 被说中了 / 安全落地；命中卡是对照式「当时担心 ↦ 实际发生 ↳ 回写决策日志」。

**停 10 秒**：展开一条「还盯着」的 💀 卡，读它的一句话假设与触发条件。

**技术决策（话术原文）**：「💀 致命漏洞假设最容易做成一次性烟花——喊一嗓子就没了。这里每条 💀 落盘**必带一个可观测触发信号**，从状态机事件里选：结构退回、原型退回、PRD 过期、决策被推翻、封板。事件发生由**状态机自动结算**，不由模型每轮自己回核——否则第 20 轮核 20 条，结局必然是机械勾『未触发』。命中了就回写决策日志，留下『当初预测 vs 实际发生』——这是复盘时最值钱的资产。」

## Step 8（3:40–4:05）调研分支 + 「这条记下来」归属分流

**动作**：对话里说：「**帮我调研下竞品**」——意图自动命中竞品分析分支技能执行，结果带出处 URL 落盘 `05-analysis/`。再说：「**这条记下来**」——弹窗出现**归属分流**（方法论卡片 / 经验记忆，默认判定可改），选「方法论卡片」生成一张卡。

**停 10 秒**：检查器里指意图命中的 trace（命中了哪个技能、为何命中）；卡片详情里的**实战注记时间线**。

**技术决策（话术原文）**：「竞品分析**不在主线上**——它是分支：技能库手动选用，或像我刚才那样对话意图自动命中。主线保持最短闭环，增值能力以分支扩展，V2 的数据分析沿用这个模板。『记下来』的归属分流是三层语义划分：**怎么做事**（方法论，不会过时、注记只增不覆盖）和**发生过什么**（经验，会过时、被覆盖）分库管理——混层的代价是双向的：把偏好当方法论跨项目复用，是过期记忆冒充通用知识。」

## Step 9（4:05–4:25）封板只读

**动作**：切到示例项目（或当前项目）点「**封板**」：release-notes 自动生成，版本目录变只读，UI 顶部黄条提示，左栏版本号出现 🔒；全部未触发 💀 统一结算为「安全落地」。

**停 10 秒**：黄条 + 🔒 + 结算后的风险列表。

**技术决策（话术原文）**：「封板是混合结构：回看 v1.0 要的是**当时那一份、逐字一致**——这是不可变快照；看『为什么 v1.1 改了方案』要的是变更过程——这是 append-only 事件流。两类内容诉求相反，拆开处理。封板时全部 💀 统一结算为未触发关闭——每条风险有始有终，悬空口径在版本边界闭合。」

## Step 10（4:25–5:00）Claude Desktop 调 MCP——胜负手

**动作**：**保持 PM Copilot 在后台不动**，切到 Claude Desktop，输入：「用 pm-copilot 的 generate_prd 给健身打卡App生成 PRD，然后轮询结果」。Claude 调用工具 → 拿到 task_id → `get_task` 轮询 → 返回 PRD 路径。切回 App——**MCP 触发的运行在界面上可见**（与 UI 共享同一条流水线状态）。

**停 10 秒**：让 Claude Desktop 的工具调用过程完整停在屏幕上，再切回 App 看同一条运行记录。

**技术决策（话术原文）**：「我的 App 在后台当 server，Claude Desktop 在前台调用它——**这一幕比任何口头解释都有说服力**。stdio 本来就是为本地进程设计的，本地 App + stdio 是 MCP 的原生形态，无远程鉴权面。长任务走异步：返回 task_id 轮询取结果。别人的工具不一定是我这个 UI——开放能力，才是别人用你的理由。」
